# Observation 6 — A transfer between parties needs one thing, and it is not in the transfer

The protocol said the honest answer to *what does a transfer between parties need that a transfer
between lines did not* may be nothing. It is nearly nothing, and the one thing it needs is not a
field.

## What the transfer asked for

The adopting party asked the repository what the other party's line would be in its own, and got the
same answer convergence measured with one writer:

```text
remove     { }
introduce  { hiring }
```

Only the hiring, because the Target already holds the budget and the transfer drops what it already
reflects. Then the party took it up, which is an ordinary fork of its own line:

```text
budget, hiring, equipment      on the adopting party's branch
```

The account admits it — 50 − 20 − 15 leaves 15, inside its bounds — and the donor's line is
untouched. Donating cost the donor nothing, because nothing moved: a commitment identity was named
in a second world.

The report's fields, asserted as a closed set:

```text
base   source   target   omitted   introduced   status
```

No party anywhere. Adding one made the assertion name it, which is the only reason the assertion is
written that way — a field nothing looks at is how an unnecessary one survives.

## The one thing it does need

A convergence experiment's writer held both lines because it had decided both. A party holds only
what it read. So when the donor has not converged, its world is in nobody's archive, and the
question cannot be asked:

```text
UnknownThesis(<the donor's world>)
```

Named, and named by the adapter rather than by the transfer. Once the donor converges, the same
question has an answer, and nothing about the transfer changed:

```text
before the donor converged   refused, the Source is nowhere
after                        applicable, introduce { hiring }
```

> Reaching each other is downstream of converging. That is the dependency, and it is the whole of
> what Part A's two halves have to do with each other.

Which is worth saying plainly because it reads like plumbing and is not. The Synthesis machinery
asks for three worlds by identity and verifies rather than searches — convergence established
that — so it is *indifferent* to how they got into the archive. What supplies them is the repair
Phase 2 built, and without it a party can name a world it decided itself and no world anybody else
did.

## What the arrangement refused when it was mutated

Applying the resolved transfer to the **Source** instead of the Target does not produce a
misfiled world: the engine refuses it as `SelectionUnchanged`, because asking a line to introduce
what it already holds changes nothing. Applying it to the **Base** produces the donor's own world
again, so the lineage does not grow.

Both are stronger than the guard that was written for them, and it is worth recording which
assertion actually answered: the count and the engine, not the check on ancestry. The ancestry check
corroborates the phase; it does not carry it.
